# qcgui 路线图

> 更新于 2026-10-14 · 对应提交 `6607716`

## 一、排序原则

**对量化工具来说，最坏的情况不是算错，而是算错了却显示绿色成功。**

这个项目已经遇到三次同一类问题：静默跳过的 NBO 分析、消除成丁二烯却报 `done` 的扫描任务、
跑满 50 圈没收敛的过渡态。用户不会去翻日志，只会看那个绿点 —— 所以优先级按：

```
结果可信度  >  交互可靠性  >  能力扩展  >  工程化
```

## 三、P0 — 结果可信度

这一档的共同特征：**做错了不会报错**。

### 1. 把"任务结论"汇成一个可见判定
现在警告分散在三处：`result.warnings`（结果面板横幅）、任务卡片的 `⚠` 徽章、界面日志。
用户要自己拼起来才知道这次计算能不能用。

**做法**：给每个任务算一个结论 —— `可用` / `可用但有限制` / **不可用**，
在任务详情顶部用一句话说清"这次结果能不能拿去写论文"。
判据来自已有的检查（静默跳过、成键变化、未收敛、orca_2json 失败）。

### 2. `orca_2json` 失败被完全吞掉（审计 E3）
`engines/orca.py` 里导出 JSON 的调用失败了没有任何记录，
结果是 `status=done`、能量与几何全空、**零警告**。
实测真实二进制在缺 `.property.txt` 时会以 exit=2 退出。

**做法**：检查返回码；失败时给出明确警告（"结构化输出导出失败，本次结果缺少能量/几何"）。

### 3. 同一秒内的重复提交会共用 job_id（审计 E1，高危）
`jobs/store.py:make_job_id()` 用"秒级时间戳 + 指纹"，同一秒提交相同参数会得到**同一个 id**：

- 两个 worker 争同一个 `.out`（引擎用 `"w"` 打开）互相截断
- `INSERT OR REPLACE` 只留一行索引
- `_procs` 字典键冲突 → `cancel()` 只杀得掉一个，另一个变孤儿进程
- 实测复现：索引只剩 1 行、目录共用、文件互相覆盖

**做法**：id 加唯一性后缀（同秒冲突时递增），或在任务层直接拒绝重复提交。

### 4. 补齐已加守卫的覆盖面
本轮已加（都经真实任务验证）：
- **成键变化检测** —— 43 个真实优化任务上 4 条命中全是真问题、39 条正常任务零误报
- **收敛检查** —— 依据 ORCA 自己的措辞，实测抓到一条跑满圈数的 OptTS
- **扫描的 180° 奇点警告** —— 实测该区间会直接崩（退出码 2）

**待补**：
- 成键检测目前只对优化类任务生效，扫描任务也该查（扫描的每一帧都可以查）
- 阈值 `_BOND_TOLERANCE = 1.25` 只在十几个分子上验证过，需要用真实任务库批量回归

## 四、P1 — 交互可靠性

### 5. SSE 断线时"运行"按钮永久禁用（审计 F1，高危）
提交后按钮只在 SSE 的 `finished` 事件里恢复。SSE 一断（服务重启、网络抖动、休眠唤醒），
事件永远收不到 → **按钮永久灰掉，唯一的自救是刷新页面**。
实测：`?nosse=1` 下任务已经 `failed`，按钮仍是 `disabled`。

**做法**：提交后启动一个兜底定时器（本轮的"任务列表轮询"已有现成套路），
任务结束或超时后强制恢复按钮。

### 6. 快速切换任务时结果面板串台（审计 F2，高危）
`selectJob` 没有请求序号保护。先点慢任务再点快任务，**慢响应后到会覆盖面板**：
标题和高亮是新任务、结果区是旧任务，扫描任务还会把 A 的曲线插进 B 的面板。

**做法**：给每次 `selectJob` 发一个递增 token，回来时不匹配就丢弃。

### 7. 「几何来源」模式下电荷/多重度被静默忽略（审计 F3）
界面填的 `-1 / 2` 不会生效，jobspec 落盘的仍是父任务的 `0 / 1`。
这正是类型 A 的问题：**用户以为改了，其实没改**。

### 8. `/api/status` 失败时界面停在半初始化（审计 F4）
芯片永远显示"检测中…"、任务类型与溶剂下拉为空，
此时提交必然失败并报 `'' is not a valid JobType`，只有点「刷新」能恢复。

### 9. 其余交互项
- 「键长响应」模式的游标圆点用了能量轴的比例，落在所有曲线之外（偏离 37 px）
- 状态芯片的 `classList` 只加不减 → 红点不消
- 轨迹播放永远到不了最后一帧
- 结果面板加载失败时保留旧内容
- ★ 收藏按钮空转

## 五、P2 — 能力扩展

### 10. 扫描结果的可视化增强（已有基础）
本轮已实现"拖动势能图换构象"。下一步可选：
- **多坐标联动画曲线**：能量 + 键长 + 键角同一张图、共享游标
- **曲线导出**：现在是 `tools/plot_scan.py` 生成 PNG，可以做成一键导出并附数据 CSV
- **扫描点的能量分解**：把每个点的能量与参考结构之差拆成"扭转 + 键长弛豫"

### 11. Multiwfn 深度集成
已验证可用的低门槛入口（**都不需要 NBO**）：
- `1` Mulliken / `8` NAO 轨道成分 → 后者需要 NBO，前者不需要
- `9` 键级（Mayer / Wiberg / Fuzzy / LBO）→ 直接读 `.molden` 就能算
- SCPA 轨道成分、AdNDP

**做法**：把 Multiwfn 的批量模式接进来，结果解析成结构化表格。
比 NBO 划算得多 —— 不需要采购、不需要新二进制。

### 12. TD-DFT / NMR / EPR 的结果解析
`orca_2json` 已经能出这些数据，引擎侧只是没解析。
对常见的有机化学问题（紫外、NMR 归属）价值直接。

### 13. 轨道等值面改 WebGL
现在是自写的 Canvas 2D 画家算法。立方体数据已经有了，改 WebGL 可以画真正的等值面。
**权衡**：会引入第一个图形依赖，与"零依赖手写前端"的现状冲突 —— 需要你决定。

## 六、P3 — 工程化

### 14. CI 修绿并稳定
现在 Linux/macOS 尚未覆盖（项目只在 Windows 上验证过）。
`requirements.txt` 与 `environment.yml` 已就绪，加 Linux 矩阵的成本很低。

### 15. 覆盖率的空洞
本轮变异测试发现三类"没有牙齿"的测试（其中两条已修）：
- 重复关键字去重**完全没有测试** ← 已补
- 原子顺序测试是自洽的、不是对照真值的 ← 已改为对照 XYZ 源文件
- 引擎的失败上报路径一条测试都没有 ← 已补 2 条

**待做**：把变异测试变成常规手段（`tools/mutation_check.py` 已就绪），
对新增的核心逻辑都跑一遍。

### 16. 打包分发
现在需要装 Python + 依赖。可选：
- PyInstaller 打成单文件 exe（体积大，但"下载即用"）
- 或维持现状，只保证 `--doctor` 能把缺什么说清楚

## 七、明确不做

| 项 | 理由 |
|---|---|
| **自研 NBO** | 没有 NBO 就无法验证自己的实现是否与它一致 —— 违反本项目"结果必须可验证"的原则 |
| 重写一个通用可视化库 | 现有查看器够用，投入产出比低 |
| 多用户 / 远程服务化 | 这是单机研究工具，没有这个需求 |
| 用正则解析 ORCA 日志取数 | 已有铁律：只从结构化输出取数 |

## 八、需要你决定的

1. **NBO 7.0 是否采购**（个人授权 $100，Windows x64，需确认 `i4` 编译）
   —— 买了就能接 NPA / NBO 轨道成分 / E(2) 稳定化能；不买的话走 Multiwfn 那条路
2. **WebGL 轨道等值面**要不要做（会引入第一个图形依赖）
3. **打包成单文件 exe** 是否有价值（面向不装 Python 的使用者）

## 九、建议的下一步（一周内可完成）

1. 修 CI 至全绿，补 Linux 矩阵
2. 做 P0 的第 1 项（任务结论判定）—— 它把已有的零散检查汇成用户真正会看的一句话
3. 修 P1 的第 5、6 项（按钮永久禁用、面板串台）—— 都是本机已复现的高危项，改动都不大
